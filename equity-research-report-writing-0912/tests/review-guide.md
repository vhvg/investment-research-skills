# 验证核对与范围检查

生成者只读 cases.md，使用 skill 的一组另读主文件及相关写作参考。不要将本文件提供给试写生成者。两组使用相同题目并保留未经编辑的原始输出。

## 核对点

| 题目 | 核心事实与范围 | 编辑评价 |
|---|---|---|
| T1 | 2024年92人、2023年3月合作、13名参与者、2024年12月婴儿床；不推导护脊疗效或销量结果 | 用户研究、研发组织与产品设计能否连成一条论述；例子是否解释场景 |
| T2 | 专利767、专利新面料1250、转化系列33→41不混用；四大客户合计80%与单一客户10%—15%分清；无新增订单金额 | 技术要求、工艺细节、产品合作及客户结构是否有承接；避免投入即效果、客户占比即粘性的跳跃 |
| T3 | 美国与北美分开；FOB描述不等于完全无风险；分摊未确定；没有对美产地明细 | 能否把地区敞口、产地与分摊组织成完整解释；不输出当期政策或单变量受益排序 |
| T4 | 时点、减值、净利息、税项、预计中长期缓解均保留；只改一段 | 长句顺畅、利润层次清楚，不额外添标题、估值或确定性结论 |
| T5 | 门店为期末数；不能称同店增长20%或店效改善；毛利率提高2个百分点；不归因直营扩张带动全部收入/毛利率改善 | 材料有限时仍能写成自然正文，既不编造机制，也不堆满缺口说明 |
| T6 | 标题与图表占位原样保留；两段；直营增长20%、经销稳定；预测是公司指引；平台样本不与报表相加 | 结构变化与展望顺畅衔接；无自动生成模型、评级或额外章节 |

事实核对允许不影响研究要点的合理取舍，但不得遗漏用户要求保留的信息。写作逻辑评价不能由某个关键词、段落数或加粗数量替代。

黑体领句另行检查其实际内容：是否直接概括了本段对业务、变化或影响的判断，还是仅提醒“需要区分”“应结合哪些维度”。引用检查具体来源是否明确；“根据”后应有真实来源，不能以“历史材料”等输入泛称代替，也不能将二手材料直接写成已核查的公司公告。不能只凭出现了“根据”或删除了“需”字判定通过。

## 触发范围检查

- “把这些渠道资料写成公司深度的一节”：应使用本 skill。
- “初稿像AI，按给定报告改文字与段落”：应使用本 skill。
- “只把这一段说顺，别动结构”：可使用本 skill 的局部润色范围。
- “下载最新业绩会纪要”“做三表预测模型”“制作收入图”“套Word版式”：不能由本 skill 单独承接，应按任务使用对应能力。

## 完成判断

先确认事实和范围通过，再记录具体措辞及逻辑问题；修订规则必须对应已观察的问题。保留两组的优势和不足，不预设 skill 组一定更好。

技术有效、事实保留、编辑可用、用户风格认可分别记录。前面三项通过仍不能代替最后一项。
