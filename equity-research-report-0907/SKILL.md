# 个股深度研究报告

## 核心约定

把报告同时视为研究结论、证据系统、图表产品、预测模型和可审阅的写作工程。专业感来自准确的对象与口径、充足的数据密度、清晰的因果链和克制的判断，不来自堆叠“我们认为”“有望”等词语。

始终执行：

- 区分披露事实、样本观察、自行测算、经营预测和研究判断，不把计划、推断或相关性写成既成事实。
- 按任务的数据截止日取材；当前研究使用最新可得资料，历史时点研究仅使用当时已公开的信息。纯文字改写保留原期间，不静默替换数字；需更新的易变信息另列核验。
- 投资判断类报告的核心论点在章节层面完成“事实与变化—原因与机制—财务影响—估值或投资含义—风险/验证指标”闭环；不要强迫每个段落重复整条链路。
- 不编造数据、访谈、门店调研、管理层表述、评级、目标价、分析师身份、机构品牌或合规声明。
- 材料不足时保留缺口、假设和待验证项；不以套话、重复背景或伪精确数字补足篇幅。
- 用户提供参考报告时，只迁移可复用的语言、结构、证据与图表规律；不复制原文、Logo、人物信息、付费图像或免责声明。

## 默认交付组合

先按用户请求确定范围，不扩大交付。用户要求完整或详细报告且报告包含图表时，默认维护以下配套文件：

1. 报告主稿：Markdown；用户要求 Word 时制作并验证 DOCX。
2. 图表底稿：一份轻量 XLSX，每个报告图/表对应一个独立工作表；各工作表前六行标明可追溯来源，其余区域按实际数据形态自由组织。
3. 证据台账：关键命题、原始来源、定位、口径、处理和报告使用位置。
4. 需要预测或估值时，简单计算留在对应图表页；跨图表的完整财务模型单独交付，图表底稿保留展示数据及模型定位。

例外：

- 用户只要研究方案、目录或框架时，只交付方案、来源地图、证据/图表计划和缺口，不扩写正文。
- 用户只要章节、若干段落或局部改写时，只完成该范围；只更新与该范围相关的底稿工作表。
- 用户明确不要底稿、只要文本，或任务本身没有图表时，遵从用户口径。

## 先确定任务范围

范围优先于后文的完整报告流程、模板和检查表：

| 任务 | 执行范围 | 预测与估值 |
|---|---|---|
| 纯文字润色、格式调整 | 修改给定材料，保留事实和判断强度；用局部正文检查 | 不新增 |
| 研究方案、目录 | 问题、来源及证据/图表计划；数量按问题决定 | 只规划任务需要的部分 |
| 单章、短评、财报事实摘要 | 完成指定问题，核对所用事实和必要图表 | 仅在用户要求或该结论确需时加入 |
| 品牌复盘、业务专题、事件分析 | 按研究问题组织完整专题 | 空间测算不自动扩展为集团三年预测或目标价 |
| 公司深度、投资价值分析、模型更新 | 完成相关研究与模型；更新任务仅修订受影响部分 | 完整覆盖默认纳入，用户另有范围时从其要求 |

不适用的模板段落直接删除；不为通过完整报告检查补写无关内容。元数据只填写实际使用的日期、币种和期间。

## 选择报告形态

先识别任务支持的决策，再选择一种主形态并读取 [references/report-archetypes.md](references/report-archetypes.md)：

| 请求 | 主形态 | 默认重点 |
|---|---|---|
| 首次覆盖、投资价值、公司深度 | 公司深度 | 业务与周期、竞争力、预测、估值 |
| 单一品牌、业务线、地区或增长极 | 品牌/分部专题 | 产品、渠道、运营阶段、空间及母公司映射 |
| 半年度策略、板块机会、主题轮动 | 行业策略 | 周期、供需价格、主线、公司弹性 |
| 重大事件、渠道、政策或竞争变化 | 事件跟踪 | 已知事实、传导、情景、产业链影响 |
| 财报、业绩预告、业绩会或模型更新 | 财报更新 | 预期差、驱动桥、预测修订、估值 |

章节顺序为研究服务。不要把所有模板章节机械拼入每份报告。

## 工作流

### 1. 锁定问题、口径与工作状态

按适用范围确定研究对象、证券代码、市场、读者、报告形态、数据截止日、估值基准日、预测期、币种、篇幅和交付格式。若用户未指定：

- 使用中文，面向熟悉财务与投资的专业读者。
- 当前研究采用最近可得财务期；仅涉及价格或估值时取对应基准日收盘价。需要新建完整盈利预测且用户未指定期限时，默认预测未来三年。
- 公司深度约 20–45 页，专题/策略约 12–30 页，事件跟踪约 6–15 页；以证据和图表密度为准，不为页数灌水。
- 未明确提供监管意义上的评级口径时，使用“研究结论”和“估值区间”，不擅自赋予买入/增持评级。

详细报告可以分段生产，不要求一次性生成全部正文。读取 [references/staged-authoring.md](references/staged-authoring.md)，复制 [assets/report-progress-template.md](assets/report-progress-template.md) 维护范围、数据日期、术语、章节状态、图表编号和未决问题。除非用户要求逐段确认，不要把每个阶段都变成新的审批点；可以连续推进并提供进度更新。

若用户只要研究方案，复制 [assets/research-plan-template.md](assets/research-plan-template.md)，达到其中完成门槛后停止。

### 2. 建立假设、证据与图表计划

读取 [references/research-evidence.md](references/research-evidence.md)。复制 [assets/evidence-ledger.csv](assets/evidence-ledger.csv)，为关键材料记录来源、日期、页码/表格/URL、原始口径、标准化处理、置信度及报告/图表使用位置。

完整投资研究通常列出 3–5 条可证伪的核心假设；专题和局部任务按实际问题确定数量，事实摘要和纯润色不强建假设树。对需要论证的假设安排：

1. 历史与当前基准；
2. 驱动机制及替代解释；
3. 支持和反方证据；
4. 进入收入、利润、现金流或估值的路径；
5. 正文段落、图表和模型输出；
6. 可观察的验证或证伪指标。

核心论点旁应有最能证明该变化的图表、表格、产品/渠道图片或模型底表。先规划“这张图回答什么问题”，再收集数据，不为装饰而画图。

### 3. 收集、核验并标准化资料

优先使用公司公告、财报、业绩会材料、监管披露、政府及行业官方数据。数据库、行业机构、主流媒体和渠道观察用于补充。社交媒体、电商截图和门店观察只证明相应样本与时点，不能直接代表全市场。

对关键数字尽量回到原始来源；来源冲突时保留冲突、解释口径并选择可辩护值。统一财年/自然年、币种、单位、税率、份额、名义/实际值以及历史 `A`、一致预期 `C`、研究预测 `E` 标记。保留原始数据，不覆盖成处理后数字。

### 4. 建立图表底稿

完整或详细报告在正式扩写正文前，读取 [references/chart-data-workbook.md](references/chart-data-workbook.md)，以 [assets/XX深度报告底稿.xlsx](assets/XX深度报告底稿.xlsx) 为起点制作底稿。交付时将 `XX` 替换为研究对象名称，文件名统一为 `{研究对象}深度报告底稿.xlsx`。

底稿必须满足：

- 第一张 `图表索引` 只保留必要映射：编号、报告章节、工作表、图表标题和状态。
- 除索引外，每个有效工作表只对应一个报告图或表；数据图用 `Fnn_`，表格用 `Tnn_`，图片/截图用 `Inn_`。
- 不预设统一数据表头、固定列数、原始/标准化/展示分区或图表位置。每页可按来源数据的真实形态自由粘贴表格、编写公式、插入图表或放置图片。
- 每个图表工作表前六行至少登记一条可追溯来源：公开材料用原始 URL；无公开链接的材料用文件名、精确定位和证据编号。格式和例外统一见图表底稿指南；口径和处理说明放在证据台账或独立模型。
- 图表标题、单位、期间、历史/预测标记和资料来源与报告一致；最终正文中的每张图表都能经由 `图表索引` 反查到唯一底稿工作表，并在该工作表顶部找到原始来源定位。
- 数据图优先使用工作簿原生图表，不把可复算数据图仅作为截图粘贴。

底稿不是资料仓库。只纳入会进入报告或直接支持模型、图表审计的数据。

### 5. 形成论点树与章节骨架

先写一句核心结论，按研究问题确定核心论点数量。投资判断类章节使用：

`结论 → 关键事实/变化 → 驱动机制 → 财务影响 → 估值/投资含义 → 风险与观察指标`

把共识与本报告新增判断分开。若一个章节不能支撑核心论点、预测、估值或风险，删去或移入附录。历史和行业背景可以先铺陈事实，但须在本节内归纳阶段判断；不要求每一段都硬接“估值影响”和“证伪条件”。

复制 [assets/report-template.md](assets/report-template.md)，先完成：

1. 标题、一句话结论与核心观点；
2. 结论型目录和段内加粗的完整概括句；
3. 图表索引、底稿工作表名及证据编号；
4. 本次任务适用的预测、估值与风险摘要；
5. 各阶段的写作边界和完成状态。

### 6. 按参考报告的文字与段落风格写正文

所有完整正文、章节起草和专业化改写均读取 [references/chinese-sell-side-prose.md](references/chinese-sell-side-prose.md) 与 [references/writing-layout.md](references/writing-layout.md)。首次起草，或用户反馈风格不佳时，再读 [references/prose-examples.md](references/prose-examples.md)：按需要选择段落改写或连续小节，区分模拟材料与参考报告历史材料。观察依据及样本页码见 [references/reference-corpus.md](references/reference-corpus.md)。

本用户参考风格的核心不是增加“研报词”，而是形成连续的分析正文：

- **完整判断句加粗领起，同段接事实、数据与解释。** 不只加粗“产品端/渠道端”，不把段首句单独排成小标题。标题已交代方向或属于事件说明、承接段时，可以直接写事实。
- 一个自然段围绕一个中心问题展开。有证据时，写清经营约束、公司做法及其实际作用；材料不足时准确描述已知变化，不靠同义复述扩写。
- 同一经营过程可以用较长复句；先检查主干、因果、比较和转折，再决定断句，不按字数强拆。专业词语按经营含义与证据选用。
- 每个小节围绕一个研究问题逐层展开；相邻段落推进新的环节或证据，减少重复背景与结论。
- 标题、领句和段尾各有分工，不重复同一个结论；通常使用一级章节、二级小节和段内领句三级视觉秩序。
- 经营正文以自然段为主，同一判断下的短并列可用①②③；摘要、预测假设和风险可分项，不把全篇正文写成清单。
- 先建立证据，再用段首句概括发现；正文按经营变量拆解。事实直接陈述，预测、测算和判断用必要标记区分，不叠加不确定词。
- “机制—财务—估值—验证”在章节层面检查。已有证据支持的判断直接表达，影响核心结论的限定就近说明，一般资料缺口和证据编号留在工作文件中。
- 只做风格改写时，保留事实、数字、时间和判断强度；不为润色补造因果、预测或资料。

先用本次真实材料完成一个代表性小节，在内部核对来源和口径，再连读检查机制展开、用词、复句及段落递进；先改小节暴露的问题，再沿用至其余章节；用户没有要求确认时连续推进。报告主标题可适度文学化，正文回到具体研究对象和经营变化。

### 7. 搭建预测与估值

本次任务需要新建或修改预测、目标价或评级时读取 [references/forecast-valuation.md](references/forecast-valuation.md)。先建驱动树，再写预测文字。新建完整模型时完成下列适用项目；单项敏感性或局部更新只处理相关输入、输出及受影响的下游结果：

- 三至五年历史财务和经营指标重述，复杂周期公司尽量覆盖更长周期；
- 收入按最贴近商业模式的业务/地区/量价/门店/产能/客户拆分；
- 毛利率、费用率、税率、少数股东、股本、现金流和净债务桥接；
- 基准情景及关键变量敏感性；
- 估值方法和可比公司选择理由；
- 当前价格、基准日、币种、股本、净债务和每股价值统一。

报告正文呈现驱动、关键假设、结果和敏感性；完整公式与底表放入可复算工作簿。预测章节常用“收入端—盈利端—关键假设—预测表”组织，不从目标 EPS 倒推假设。

### 8. 设计页面与成品

参考报告采用“正文—图表—来源—下一结论”的高密度节奏。每张图表回答一个研究问题，在正文中被解释，并紧邻其支撑的段落。可将两张可读的小图并排；趋势长、分类多或表格复杂时使用整页宽度。

用户要求 DOCX 时调用文档制作能力并遵循模板/渲染检查流程。用户提供授权模板时，以模板为版式权威；无模板时使用中性机构研究样式，不复制参考报告的 Logo、分析师照片、执业编号、评级定义或免责声明。

### 9. 交付前审计

读取 [references/qa-checklist.md](references/qa-checklist.md)，按任务范围检查适用项目：

1. 证据审计：核心数字、判断和图表可回溯，引用与原文一致；
2. 数字审计：历史、预测、估值、单位以及报告与底稿完全一致；
3. 反方审计：替代解释、证伪条件和主要风险已处理；
4. 语言审计：主语、期间、口径和认识层级明确；完整领句与解释同段，正文连贯、标题层级适度，无标签堆叠或重复段尾；
5. 图表底稿审计：每个报告图/表都有唯一工作表、可复算数据，并在工作表顶部登记可追溯来源；
6. 成品审计：标题、目录、图表、来源、页码、版式和附件完整。

完整研究稿用默认模式；单章、短评、事实摘要及纯润色用 `--fragment`，并人工核对本次范围内的日期、来源和必要风险：

```bash
python scripts/lint_research_draft.py /absolute/path/to/draft.md
python scripts/lint_research_draft.py --fragment /absolute/path/to/excerpt.md
```

对图表底稿运行：

```bash
python scripts/validate_chartbook.py /absolute/path/to/chartbook.xlsx --report /absolute/path/to/report-master.md
```

底稿脚本可检查映射、正文图题、已存储的单元格错误和缺失公式缓存；不重算公式，不证明来源真实或正文数字正确。局部主稿追加 `--report-fragment`；格式要求及人工数值勾稽见图表底稿指南。解决适用检查中的所有阻断项，并逐条判断警告是否合理。语言脚本只辅助定位，不要求为通过长度或密度提示而机械拆段、补字或加粗；仍须连读全文检查。DOCX 必须在最终修改后重新渲染逐页检查；XLSX 必须检查关键数据、公式错误、工作表映射并完成全表视觉预览。

## 参考语料模式

本 skill 的语言、结构和图表规则依据 21 份用户提供的中文机构研究 PDF 重新校准。需要理解样本边界或继续迭代写作风格时读取 [references/reference-corpus.md](references/reference-corpus.md)。原始报告不捆绑进 Skill；只保留可迁移规律和可审计模板。

## 交付标准

交付时说明本次适用的数据截止日、估值基准日、预测期、关键假设、未解决资料缺口和文件清单；局部任务不补列无关字段。完整报告的正文、图表底稿、模型和封面关键数字必须一致。把事实写得明确，把判断写得有依据，把不确定性写得可检验。报告用于研究交流，不包装成针对个人财务状况的投资建议。
