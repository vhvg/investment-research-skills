# 长报告分段撰写与续写

## 何时使用

公司深度、投资价值分析、品牌专题、行业策略及其他资料量大、图表多或预计超过约 12 页的报告，可以分段研究和写作。用户明确要求一次性交付时仍可在内部按阶段完成，最后一次性呈现成稿。

分段不是降低完整性，也不是把未经核验的半成品依次发给用户。它的目的，是让研究、图表、预测和文字在每一阶段都可追踪、可恢复、可修订。

## 持久工作状态

以 `assets/report-progress-template.md` 建立进度文件，并按实际交付范围同步维护：

- `report-master.md`：唯一主稿，不把多个版本散落为互相冲突的章节文件；
- `report-progress.md`：范围、口径、术语、章节状态、图表编号、数字基准和未决问题；
- `chartbook.xlsx`：图表索引和逐图逐表底稿；
- `evidence-ledger.csv`：证据、定位、处理和使用位置。

开始正文前在进度文件记录选定的参考报告/页码、标题层级、领句方式及段落格式，后续批次沿用。首次起草或风格反馈后，用当前任务材料在内部校准一个代表性小节：先核对事实与归因，再连读其机制、复句和段落推进，按实际问题修订写法；无需新增用户审批。

开始正文前锁定数据截止日、估值基准日、币种、预测期、公司/品牌英文名、核心指标口径和图表编号规则。后续如需变更，在进度文件记录变更原因和受影响章节。

## 分段方式

按论证依赖划分批次，不按机械页数截断。典型顺序如下，可按报告形态调整：

1. 前置骨架：一句话结论、核心观点、目录、来源地图和图表索引。
2. 基础事实：公司/品牌概况、业务构成、历史阶段、治理与历史财务。
3. 外部与能力：行业、竞争格局、产品、供应链、渠道、营销、客户或产能。
4. 前瞻逻辑：增长空间、核心投资逻辑、经营驱动和催化剂。
5. 财务闭环：盈利预测、估值、情景、证伪条件和风险。
6. 整合终稿：摘要、标题、目录、图表、来源、附录和版式审计。

有依赖关系时先完成上游。例如盈利预测依赖门店/产能/品类假设，先完成相应经营章节和底稿，再写预测结论。

## 每个批次的完成门槛

一个批次只有同时满足以下条件才标为完成：

- 章节标题和段内完整概括句与本节结论一致，领句与解释同段；
- 关键事实已进入证据台账，数字带期间、单位和来源；
- 本节图表在 `图表索引` 中有稳定编号和对应工作表；
- 正文解释了图表，而不是仅放图不作判断；
- 新增预测或判断的依据、假设与时间清楚，关键验证指标记录于本节合适位置或跟踪文件；
- 与已完成章节不存在数字、术语和结论冲突；
- 未取得的数据保留为缺口，不以推断填入。

批次完成后运行局部正文检查：

```bash
python scripts/lint_research_draft.py --fragment /absolute/path/to/excerpt.md
```

对新增图表运行底稿校验，并把完成状态、警告和下一步写入进度文件。

## 续写前的恢复顺序

每次继续工作时先读取：

1. 用户最新要求；
2. `report-progress.md` 中的固定口径和未决事项；
3. `report-master.md` 的核心观点、上一节结尾和待写章节；
4. `图表索引` 中已使用的编号、标题和状态；
5. 与本批次直接相关的证据和模型工作表。

不要只根据最后一段文字续写。先确认当前结论是否因新财报、价格或来源更新而失效。

## 分段过程中的一致性控制

- 主稿只有一个权威版本。章节草稿合并后，临时文件不再作为事实来源。
- 图表编号在首次引用后保持稳定；新增图表使用新编号，不因删图让既有引用整体漂移。
- 相同指标在全文使用同一币种、单位、财年和小数位；预测修订同步更新封面、摘要、正文、表格和估值。
- 同一事实不在多个章节重复长篇解释。后文只补充新机制或直接引用前文结论。
- 后续证据推翻早期判断时，直接修订旧章节并在进度文件记录，不把互相冲突的两个版本同时保留。
- 分段输出给用户时说明本段范围和仍待完成部分，但不要把临时研究标签或内部审计备注写入最终正文。

## 用户交互

用户要求分段查看或逐节确认时，在自然章节边界交付，并等待其反馈。用户只是允许分段但仍要求最终完成时，可连续推进，无需每段停下询问；用简短进度更新说明已经完成的部分、当前处理的部分和剩余工作。

最终整合后对整份主稿按任务范围重新检查；完整研究报告运行完整检查，短评或事实摘要等使用局部模式并人工核验其必要字段。局部检查通过不代表跨章节数字、图表和估值已经勾稽。
