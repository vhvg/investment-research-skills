# 个股深度报告底稿

## 目标

图表底稿用于保存报告每张图、表或图片的支撑数据，并让另一位研究者能直接找到原始来源。

保持工作簿开放、轻量。真实资料可能是横向时间序列、纵向明细、矩阵、截图、模型输出或不规则表格；不要为了套模板而强行改造成统一的“期间/类别 + 系列”结构。

完整或详细报告只要包含图表，默认同时维护一份 XLSX。以 `assets/XX深度报告底稿.xlsx` 为起点，用电子表格能力制作、计算、渲染和验证。

## 工作簿结构

### 1. 图表索引

第一张工作表固定为 `图表索引`。每行对应报告中的一张图、表或图片，只保留：

| 字段 | 填写要求 |
|---|---|
| 编号 | 与正文一致，如 `图1`、`表1` |
| 报告章节 | 图表所在章节 |
| 工作表 | 唯一对应的底稿工作表名 |
| 图表标题 | 与报告使用的图题或表题一致 |
| 状态 | 计划 / 已取数 / 已完成 / 停用 |

`图表索引` 只负责映射，不重复维护来源。编号首次进入正文后保持稳定；删除图表时标为“停用”，不要打乱已使用的引用。停用行可保留用于追踪，其工作表可保留或删除，但不进入正文；有效行的编号和工作表均须唯一。交付终稿时，正文使用的图表状态应为“已完成”。

### 2. 一张图表一个工作表

除 `图表索引` 和 `_图表模板` 外，每个有效工作表只对应一张报告图、表或图片：

- `F01_简短主题`：数据图；
- `T01_简短主题`：数据表、预测表、估值表或模型摘要；
- `I01_简短主题`：产品图片、渠道截图或其他视觉样本。

每个工作表仅有一项固定要求：在前六行标清数据来源。

- 至少登记一条可追溯来源；公开材料填写完整原始 URL；
- 有多个来源时继续填写第二、第三条，或按需增加来源行；
- 优先链接公司公告、财报、交易所文件、政府/协会数据库或原始网页，不链接搜索结果页和二次转载页；
- 若原始材料确实没有公开链接，使用 `数据来源：本地材料：文件名；定位：精确位置；证据：S001`。例如 `数据来源：本地材料：公司访谈纪要.pdf；定位：第3页；证据：S001`。工作簿可写工作表与单元格，访谈可写日期及段落或时间戳。证据台账须保留文件位置、材料性质和使用限制；核对实际文件与定位。只有“公司资料”或一个本地路径不够；不能用此例外省略已有公开链接。
- 自行测算或预测仍登记基础输入来源，并标明研究者测算/预测；“模型输出”本身不能替代输入证据。跨文件模型的文件名、工作表、单元格及版本放在该图表页注释或证据台账。

来源行以下全部自由使用。可以原样粘贴来源数据，也可以按实际需要加入辅助计算、预测、图表、图片和注释。不要强制使用统一表头、固定列数、固定方向或固定图表位置，也不要另设元数据区、标准化区和展示区。

简单计算放在其服务的图表页；跨图表的完整预测或估值模型使用独立工作簿，不在图表底稿新增无图表对应的模型页。图表页保留实际展示数据、必要公式及模型定位；独立模型不运行此图表结构校验，按模型审计规则复核。若导入模型计算结果，应保留可复算模型及导入版本，不能只交付无来源的静态数值。

## 数据和图表要求

- 保留数据原有的可读结构，只有在口径统一或图表制作需要时才转换。
- 推导值使用清晰公式，避免无法解释的硬编码数字。
- 数据图尽量使用工作簿原生图表，避免只粘贴不可复算的截图。
- 表格保留报告实际展示的精确数值、单位和历史 `A` / 一致预期 `C` / 研究预测 `E` 标记。
- 标题、坐标轴、图例、单位和期间在正常缩放下可读。
- 图片工作表直接放置报告拟使用的图片，顶部登记原始页面链接；无公开页面时按本地材料规则登记。
- 图表关键数字须与报告正文、预测表和估值结果一致。

## 与主稿映射

工作稿可在图题附近保留内部标记：

```markdown
图1：2019–2026E 分地区收入及增速
<!-- 底稿：F01_分地区收入 -->
```

最终 DOCX/PDF 可以移除内部标记。通过 `图表索引` 找到对应工作表，再从该工作表顶部取得公开链接或本地材料定位；报告图表下方的“资料来源”文字应与登记的原始材料名称一致。

## 更新与检查

每次新增或修改图表后：

1. 在 `图表索引` 更新编号、章节、工作表、标题和状态；
2. 确认对应工作表前六行已填写公开链接或完整本地来源登记；
3. 检查一个工作表只服务一张报告图或表；
4. 复核数据、公式、单位和 A/C/E 标记；
5. 将关键数值与正文、封面、预测和估值勾稽；
6. 渲染相关工作表，确认内容无截断；
7. 运行 `scripts/validate_chartbook.py`。

最终工作簿统一命名为 `{研究对象}深度报告底稿.xlsx`，例如 `安踏体育深度报告底稿.xlsx`。判断它是否合格的标准很简单：能从索引找到图表工作表，能从工作表顶部定位原始来源，数据本身不因模板限制而失真。


## 自动检查与人工复核的分工

```bash
python scripts/validate_chartbook.py chartbook.xlsx --report report-master.md
```

`--report` 接受 Markdown 或纯文本主稿。图题单独一行，使用 `图1：标题`、`表1：标题` 或 `图表1：标题`（允许 Markdown 标题或加粗）；索引编号和标题与其一致。脚本忽略代码块和 HTML 注释，不把行文中的“见图1”作为图题。片段配合 `--report-fragment`，只检查出现的图题；完整主稿则双向检查，避免漏图。若源稿格式无法按此识别，人工逐项核对，不能把“未识别”当成“没有图表”。最终 DOCX/PDF 的图号、图题与主稿再做一次对照。

脚本检查索引缺项、重复编号、双向工作表映射、停用图表误用、主稿图题差异、单元格已有错误值、公式中的失效引用，以及公式结果缓存缺失。URL 仅检查登记形式；本地材料输出人工复核提醒。脚本不联网验证来源，不重算公式，不判断缓存是否过期，不验证所有公式逻辑或任意正文数字。

数值复核先用可用计算引擎重算模型及底稿，再检查错误和关键公式。对摘要、预测表、估值结果及支撑核心结论的数字，逐项对照“主稿位置—工作表/单元格—原值—单位换算—展示精度”；勾稽记录留在进度文件，避免为此加宽图表索引。百分比与百分点、亿元与百万元、历史与预测分别核对；不得只用数字字符串在文件中出现过作为一致性证据。若环境不能重算，说明未完成的验证及替代复核，不把缓存存在表述为公式已算对。
