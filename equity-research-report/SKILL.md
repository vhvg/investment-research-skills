# 撰写权益深度研究报告

## 核心约定

把报告同时视为研究结论、证据系统、预测模型和阅读产品。先回答“为什么现在值得研究、市场可能错在哪里、什么会证明或推翻判断”，再安排章节和图表。

始终执行以下规则：

- 区分事实、测算、预测和判断，不把推断写成已证实事实。
- 让每个核心结论落到可核验来源、驱动变量和财务影响。
- 使用最新可得数据并写明数据截止日；对可能变化的信息重新检索。
- 不编造数据、访谈、门店调研、管理层表述、评级、目标价、分析师身份或合规声明。
- 在材料不足时交付研究缺口、待验证假设和可继续写作的骨架，不用空话补足篇幅。

## 选择报告形态

先识别用户真正需要的决策，再选择一种主形态：

| 请求 | 主形态 | 默认重点 |
|---|---|---|
| 首次覆盖、投资价值、公司深度 | 公司深度 | 商业模式、行业、竞争优势、预测、估值 |
| 单一品牌、业务线、地区或增长极 | 品牌/分部专题 | 发展史、运营能力、竞争力、空间测算、母公司映射 |
| 半年度策略、板块机会、主题轮动 | 行业策略 | 周期位置、供需价格、主线、公司映射、催化剂 |
| 重大事件、渠道变化、政策或竞争变化 | 事件跟踪 | 事实、传导机制、情景、产业链赢家与输家 |
| 财报更新、业绩预告、业绩会 | 财报更新 | 预期差、驱动拆解、预测修订、估值与后续观察 |

读取 [references/report-archetypes.md](references/report-archetypes.md)，选择并裁剪章节。不要把所有章节机械拼进每一份报告。

## 工作流

### 1. 锁定问题与交付口径

确定研究对象、证券代码、市场、读者、报告形态、数据截止日、预测期、币种、篇幅和交付格式。若用户未指定，采用以下默认值：

- 使用中文，面向熟悉财务与投资的专业读者。
- 采用最近可得财务期与收盘价，预测未来三年。
- 公司深度约 20–40 页，专题/策略约 12–25 页，事件跟踪约 6–12 页；以信息密度为准，不为页数灌水。
- 输出 Markdown 初稿；用户要求 Word 时再制作并验证 DOCX；用户要求可复算模型时同时制作表格模型。
- 未明确要求监管意义上的评级时，使用“研究结论”和“估值区间”，不擅自赋予“买入/增持”等评级。

只有评级定义、目标价基准日、授权品牌模板或关键内部资料确实会改变结果时才追问。其余信息可在显式假设下继续。

若用户只要研究方案、研究框架或详细目录，复制 [assets/research-plan-template.md](assets/research-plan-template.md)，仅交付研究问题、待证伪假设、来源地图、证据台账、模型/图表计划、详细目录和资料缺口，然后停止。不要扩写完整正文，也不要用完整成稿检查器强行检查方案稿。

### 2. 建立研究计划与证据台账

读取 [references/research-evidence.md](references/research-evidence.md)。复制 [assets/evidence-ledger.csv](assets/evidence-ledger.csv) 建立台账，为每条关键材料记录来源、日期、定位、单位、口径和证据类型。

先列出 3–5 条待证伪的核心假设，再为每条假设安排证据：

1. 现状和历史基准是什么。
2. 驱动机制是什么。
3. 哪些数据支持或反驳机制。
4. 机制如何进入收入、利润、现金流或估值。
5. 什么事件会证实或推翻判断。

### 3. 收集并核验资料

优先使用公司公告、财报、业绩会材料、监管披露、政府和行业官方数据。把数据库、行业机构、主流媒体和渠道观察作为补充。社交媒体、电商截图和门店观察只能证明对应样本与时点，不能直接代表全市场。

对高时效数据联网核验。对同一关键数字尽量找到原始来源；来源冲突时保留冲突、解释口径并选择可辩护值。统一会计期、币种、税率、份额口径、名义/实际值和历史/预测标记。

### 4. 形成论点树

先写一句核心判断，再写 3–5 条论点。让每条论点遵循同一条链路：

`结论 → 机制 → 证据 → 预测影响 → 估值影响 → 证伪条件`

反向检查章节：若一个章节不能支撑论点、估值或风险，删去或移入附录。把共识观点与本报告新增判断分开写，明确“市场已知”和“仍可能被低估/高估”的差异。

### 5. 搭建预测与估值

涉及预测、目标价或评级时读取 [references/forecast-valuation.md](references/forecast-valuation.md)。先建立驱动树，再写结论。至少完成：

- 历史财务与经营指标重述和勾稽。
- 收入、毛利率、费用、税率、少数股东与股本假设。
- 基准、乐观、悲观或等价的敏感性分析。
- 与商业模式相匹配的估值方法及可比公司选择理由。
- 当前价格、估值基准日、币种、股本和净债务的统一。

复杂模型应单独保存在可复算表格中。报告正文只呈现驱动、关键假设、结果和敏感性，不堆叠无法审阅的公式。

### 6. 先搭骨架，再填正文

复制 [assets/report-template.md](assets/report-template.md) 作为起点，按所选形态删除无关章节。先完成以下内容再扩写正文：

1. 标题与一句话结论。
2. 三至五条核心观点。
3. 每章的结论型标题。
4. 图表清单与证据编号。
5. 盈利预测、估值与风险摘要。

读取 [references/writing-layout.md](references/writing-layout.md) 和 [references/chinese-sell-side-prose.md](references/chinese-sell-side-prose.md) 后写正文。根据段落功能选择“结论先行、事实铺垫或传导拆解”骨架：投资逻辑、预测和估值优先前置结论；历史、定义和经营复盘可先给时间或事实锚点，但须在段内或紧邻段落完成阶段判断。不要机械以“我们认为”起笔，也不要先堆多页背景、最后才给结论。

### 7. 设计图表与页面

让每张图表回答一个问题。图表标题写清指标、对象和期间，预测年份标记 `E`，并在图表下方逐一写出来源和必要注释。正文必须解释图表带来的判断，不能把图表当装饰。

若用户要求 DOCX，调用文档制作能力并遵循模板/渲染检查流程；若用户提供授权模板，保持模板为版式权威。若无模板，使用中性机构研究样式，不复制参考券商的 Logo、分析师照片、执业编号、评级声明或免责声明。

### 8. 执行交付前审计

读取 [references/qa-checklist.md](references/qa-checklist.md)。至少完成四次独立检查：

1. 证据检查：核心数字和判断可回溯，引用与原文一致。
2. 数字检查：历史数据勾稽、预测桥接、估值与单位一致。
3. 反方检查：写出证伪条件、替代解释和主要风险。
4. 成品检查：标题、目录、图表、来源、页码、版式和附件完整。

对完整的 Markdown、纯文本或 DOCX 报告草稿运行：

```bash
python scripts/lint_research_draft.py /absolute/path/to/draft.md
```

若用户只要求一个章节、若干段落或局部改写，改用：

```bash
python scripts/lint_research_draft.py --fragment /absolute/path/to/excerpt.md
```

解决全部阻断项，并逐条判断警告是否合理。DOCX 必须在最终修改后重新渲染并逐页检查。

研究方案稿不运行该检查器；改用方案模板末尾的“方案完成门槛”。

## 参考报告模式

用户要求贴近本次七份参考报告时，同时读取 [references/reference-corpus.md](references/reference-corpus.md) 和 [references/chinese-sell-side-prose.md](references/chinese-sell-side-prose.md)。继承其结论型层级、事实先行的客观底色、克制判断、证据—图表节奏以及预测和估值闭环；不要复制原文、机构视觉身份或合规文本。

用户以后提供新的参考 DOCX 时，可运行：

```bash
python scripts/extract_reference_report.py --out-dir /absolute/path/to/audit /absolute/path/to/reference.docx
```

先检查结构证据，再决定是否更新写作规则。不要把大体积原始报告直接捆绑进 Skill。

## 交付标准

报告完成时同时说明数据截止日、估值基准日、关键假设、仍未解决的资料缺口和交付文件。把事实结论写得明确，把不确定性写得可检验。报告用于研究交流，不把它包装成针对个人财务状况的投资建议。
