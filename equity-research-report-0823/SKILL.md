# 个股深度研究报告

## 核心约定

把报告同时视为研究结论、证据系统、图表产品、预测模型和可审阅的写作工程。专业感来自准确的对象与口径、充足的数据密度、清晰的因果链和克制的判断，不来自堆叠“我们认为”“有望”等词语。

始终执行：

- 区分披露事实、样本观察、自行测算、经营预测和研究判断，不把计划、推断或相关性写成既成事实。
- 使用最新可得数据并写明数据截止日；价格、估值、排名、管理层和其他易变信息在交付前重新核验。
- 每条核心论点在章节层面完成“事实与变化—原因与机制—财务影响—估值或投资含义—风险/验证指标”闭环；不要强迫每个段落重复整条链路。
- 不编造数据、访谈、门店调研、管理层表述、评级、目标价、分析师身份、机构品牌或合规声明。
- 材料不足时保留缺口、假设和待验证项；不以套话、重复背景或伪精确数字补足篇幅。
- 用户提供参考报告时，只迁移可复用的语言、结构、证据与图表规律；不复制原文、Logo、人物信息、付费图像或免责声明。

## 默认交付组合

先按用户请求确定范围，不扩大交付。用户要求完整或详细报告且报告包含图表时，默认维护以下配套文件：

1. 报告主稿：Markdown；用户要求 Word 时制作并验证 DOCX。
2. 图表底稿：一份轻量 XLSX，每个报告图/表对应一个独立工作表；各工作表前几行标明原始来源链接，其余区域按实际数据形态自由组织。
3. 证据台账：关键命题、原始来源、定位、口径、处理和报告使用位置。
4. 需要预测或估值时，财务模型可在图表底稿中分块维护，也可按复杂度单独交付可复算模型。

例外：

- 用户只要研究方案、目录或框架时，只交付方案、来源地图、证据/图表计划和缺口，不扩写正文。
- 用户只要章节、若干段落或局部改写时，只完成该范围；只更新与该范围相关的底稿工作表。
- 用户明确不要底稿、只要文本，或任务本身没有图表时，遵从用户口径。

## 选择报告形态

先识别任务支持的决策，再选择一种主形态并读取 [references/report-archetypes.md](references/report-archetypes.md)：

| 请求 | 主形态 | 默认重点 |
|---|---|---|
| 首次覆盖、投资价值、公司深度 | 公司深度 | 业务与周期、竞争力、预测、估值 |
| 单一品牌、业务线、地区或增长极 | 品牌/分部专题 | 产品、渠道、运营阶段、空间及母公司映射 |
| 半年度策略、板块机会、主题轮动 | 行业策略 | 周期、供需价格、主线、公司弹性 |
| 重大事件、渠道、政策或竞争变化 | 事件跟踪 | 已知事实、传导、情景、产业链影响 |
| 财报、业绩预告、业绩会或模型更新 | 财报更新 | 预期差、驱动桥、预测修订、估值 |

章节顺序为研究服务。不要把所有模板章节机械拼入每份报告。

## 工作流

### 1. 锁定问题、口径与工作状态

确定研究对象、证券代码、市场、读者、报告形态、数据截止日、估值基准日、预测期、币种、篇幅和交付格式。若用户未指定：

- 使用中文，面向熟悉财务与投资的专业读者。
- 采用最近可得财务期和收盘价，预测未来三年。
- 公司深度约 20–45 页，专题/策略约 12–30 页，事件跟踪约 6–15 页；以证据和图表密度为准，不为页数灌水。
- 未明确提供监管意义上的评级口径时，使用“研究结论”和“估值区间”，不擅自赋予买入/增持评级。

详细报告可以分段生产，不要求一次性生成全部正文。读取 [references/staged-authoring.md](references/staged-authoring.md)，复制 [assets/report-progress-template.md](assets/report-progress-template.md) 维护范围、数据日期、术语、章节状态、图表编号和未决问题。除非用户要求逐段确认，不要把每个阶段都变成新的审批点；可以连续推进并提供进度更新。

若用户只要研究方案，复制 [assets/research-plan-template.md](assets/research-plan-template.md)，达到其中完成门槛后停止。

### 2. 建立假设、证据与图表计划

读取 [references/research-evidence.md](references/research-evidence.md)。复制 [assets/evidence-ledger.csv](assets/evidence-ledger.csv)，为关键材料记录来源、日期、页码/表格/URL、原始口径、标准化处理、置信度及报告/图表使用位置。

先列出 3–5 条可证伪的核心假设，再为每条假设安排：

1. 历史与当前基准；
2. 驱动机制及替代解释；
3. 支持和反方证据；
4. 进入收入、利润、现金流或估值的路径；
5. 正文段落、图表和模型输出；
6. 可观察的验证或证伪指标。

核心论点旁应有最能证明该变化的图表、表格、产品/渠道图片或模型底表。先规划“这张图回答什么问题”，再收集数据，不为装饰而画图。

### 3. 收集、核验并标准化资料

优先使用公司公告、财报、业绩会材料、监管披露、政府及行业官方数据。数据库、行业机构、主流媒体和渠道观察用于补充。社交媒体、电商截图和门店观察只证明相应样本与时点，不能直接代表全市场。

对关键数字尽量回到原始来源；来源冲突时保留冲突、解释口径并选择可辩护值。统一财年/自然年、币种、单位、税率、份额、名义/实际值以及历史 `A`、一致预期 `C`、研究预测 `E` 标记。保留原始数据，不覆盖成处理后数字。

### 4. 建立图表底稿

完整或详细报告在正式扩写正文前，读取 [references/chart-data-workbook.md](references/chart-data-workbook.md)，以 [assets/XX深度报告底稿.xlsx](assets/XX深度报告底稿.xlsx) 为起点制作底稿。交付时将 `XX` 替换为研究对象名称，文件名统一为 `{研究对象}深度报告底稿.xlsx`。

底稿必须满足：

- 第一张 `图表索引` 只保留必要映射：编号、报告章节、工作表、图表标题和状态。
- 除索引外，每个有效工作表只对应一个报告图或表；数据图用 `Fnn_`，表格用 `Tnn_`，图片/截图用 `Inn_`。
- 不预设统一数据表头、固定列数、原始/标准化/展示分区或图表位置。每页可按来源数据的真实形态自由粘贴表格、编写公式、插入图表或放置图片。
- 每个图表工作表只在前几行维护原始来源链接：第一条必填，补充来源按需增加；使用完整、可访问的原始 URL。更详细的页码、口径和处理说明放在证据台账或独立模型。
- 图表标题、单位、期间、历史/预测标记和资料来源与报告一致；最终正文中的每张图表都能经由 `图表索引` 反查到唯一底稿工作表，并在该工作表顶部找到原始链接。
- 数据图优先使用工作簿原生图表，不把可复算数据图仅作为截图粘贴。

底稿不是资料仓库。只纳入会进入报告或直接支持模型、图表审计的数据。

### 5. 形成论点树与章节骨架

先写一句核心结论，再写 3–5 条核心论点。章节层面使用：

`结论 → 关键事实/变化 → 驱动机制 → 财务影响 → 估值/投资含义 → 风险与观察指标`

把共识与本报告新增判断分开。若一个章节不能支撑核心论点、预测、估值或风险，删去或移入附录。历史和行业背景可以先铺陈事实，但须在本节内归纳阶段判断；不要求每一段都硬接“估值影响”和“证伪条件”。

复制 [assets/report-template.md](assets/report-template.md)，先完成：

1. 标题、一句话结论与核心观点；
2. 结论型目录和段首功能标签；
3. 图表索引、底稿工作表名及证据编号；
4. 盈利预测、估值与风险摘要；
5. 各阶段的写作边界和完成状态。

### 6. 按机构研究语言写正文

所有完整正文、章节起草和专业化改写均读取 [references/chinese-sell-side-prose.md](references/chinese-sell-side-prose.md) 与 [references/writing-layout.md](references/writing-layout.md)。默认采用本 Skill 所总结的 21 份参考报告风格：

- 章节标题或段首标签先限定研究对象并给出方向，如“业务梳理：……”“分地区：……”“收入端：……”。
- 先写已发生事实和关键数据，再解释机制；预测或判断放在证据边界之后。
- 经营章节优先按量价、品类、地区、渠道、客户、产能、店效或利润率拆分，避免抽象谈“品牌力”和“成长空间”。
- 数据密集段可用 `①②③`、分业务小标题或项目符号，但正文仍应连贯，不把整份报告写成清单。
- 一般一句承载一层逻辑；长句在因果、并列或事实/预测换挡处断开。
- 使用“我们认为/预计/有望”标示认识边界，不把它们当成专业感装饰。

报告主标题可以适度文学化；正文标题、图题、预测和估值必须回到具体研究语言。

### 7. 搭建预测与估值

涉及预测、目标价或评级时读取 [references/forecast-valuation.md](references/forecast-valuation.md)。先建驱动树，再写预测文字。至少完成：

- 三至五年历史财务和经营指标重述，复杂周期公司尽量覆盖更长周期；
- 收入按最贴近商业模式的业务/地区/量价/门店/产能/客户拆分；
- 毛利率、费用率、税率、少数股东、股本、现金流和净债务桥接；
- 基准情景及关键变量敏感性；
- 估值方法和可比公司选择理由；
- 当前价格、基准日、币种、股本、净债务和每股价值统一。

报告正文呈现驱动、关键假设、结果和敏感性；完整公式与底表放入可复算工作簿。预测章节常用“收入端—盈利端—关键假设—预测表”组织，不从目标 EPS 倒推假设。

### 8. 设计页面与成品

参考报告采用“正文—图表—来源—下一结论”的高密度节奏。每张图表回答一个研究问题，在正文中被解释，并紧邻其支撑的段落。可将两张可读的小图并排；趋势长、分类多或表格复杂时使用整页宽度。

用户要求 DOCX 时调用文档制作能力并遵循模板/渲染检查流程。用户提供授权模板时，以模板为版式权威；无模板时使用中性机构研究样式，不复制参考报告的 Logo、分析师照片、执业编号、评级定义或免责声明。

### 9. 交付前审计

读取 [references/qa-checklist.md](references/qa-checklist.md)，至少完成：

1. 证据审计：核心数字、判断和图表可回溯，引用与原文一致；
2. 数字审计：历史、预测、估值、单位以及报告与底稿完全一致；
3. 反方审计：替代解释、证伪条件和主要风险已处理；
4. 语言审计：主语、期间、口径、比较基准和认识层级明确；
5. 图表底稿审计：每个报告图/表都有唯一工作表、可复算数据，并在工作表顶部登记原始来源链接；
6. 成品审计：标题、目录、图表、来源、页码、版式和附件完整。

对完整报告或局部正文运行：

```bash
python scripts/lint_research_draft.py /absolute/path/to/draft.md
python scripts/lint_research_draft.py --fragment /absolute/path/to/excerpt.md
```

对图表底稿运行：

```bash
python scripts/validate_chartbook.py /absolute/path/to/chartbook.xlsx
```

解决所有阻断项，并逐条判断警告是否合理。DOCX 必须在最终修改后重新渲染逐页检查；XLSX 必须检查关键数据、公式错误、工作表映射并完成全表视觉预览。

## 参考语料模式

本 skill 的语言、结构和图表规则依据 21 份用户提供的中文机构研究 PDF 重新校准。需要理解样本边界或继续迭代写作风格时读取 [references/reference-corpus.md](references/reference-corpus.md)。原始报告不捆绑进 Skill；只保留可迁移规律和可审计模板。

## 交付标准

交付时说明数据截止日、估值基准日、预测期、关键假设、未解决资料缺口和文件清单。完整报告的正文、图表底稿、模型和封面关键数字必须一致。把事实写得明确，把判断写得有依据，把不确定性写得可检验。报告用于研究交流，不包装成针对个人财务状况的投资建议。
